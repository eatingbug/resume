## 문제

팀에 합류했을 때 프롬프트는 Python 코드 안의 문자열이었다. 프롬프트를 고치려면 서버를 다시 배포해야 했다. LLM 채점이 핵심 기능이라, 품질이 떨어진 프롬프트가 학생에게 나가면 안 됐다.

| 상황 | 위험 |
|---|---|
| 프롬프트가 Python 코드 안의 문자열 | 읽고 고치기 어려움, 바꿀 때마다 재배포 |
| 작은 프롬프트 수정 | 채점 결과가 바뀔 수 있음 |
| 병합 전 자동 평가 없음 | 품질 저하를 운영에서야 발견 |

## 판단

**프롬프트 변경은 평가 게이트를 통과해야 병합된다.** 병합된 버전은 재배포 없이 AI 서버에 반영된다.

| 대안 | 장점 | 고르지 않은 이유 |
|---|---|---|
| YAML 파일로 분리 (1단계) | 코드 가독성·유지보수 | 여전히 서버와 함께 배포 |
| 게이트 없이 Langfuse 배포 (2단계) | 재배포 없이 교체 | 품질 저하를 병합 전에 못 잡음 |
| 운영 A/B 테스트 | 실제 트래픽으로 비교 | 성능 저하 위험을 학생에게 노출 |

- **세 단계로 옮겼다.** 먼저 프롬프트를 YAML 파일로 분리했다. 다음에 프롬프트 저장소로 떼어 Langfuse로 배포·버전 관리했다. 마지막에 평가 게이트를 붙였다.
- **운영 A/B는 하지 않았다.** LLM이 핵심 기능이라, 성능이 떨어질 수 있는 버전을 학생에게 보이지 않기로 했다.
- **게이트는 절대 기준과 상대 기준을 함께 쓴다.** 일부 지표는 임계치를 넘어야 한다. 일부 항목은 기준 버전과 비교한다. 승자는 rubric 준수 점수로 정한다.
- **미세한 차이는 통과로 본다.** LLM 출력은 매번 조금씩 다르다. 기준 버전보다 나쁘다고 판정되지 않으면 통과다(비열등성 판정).

## 구현

{% include diagrams/prompt-cicd-gate.html %}

- **흐름:** 프롬프트 변경 PR (프롬프트 저장소) → CI 평가 (평가 데이터셋) → 통과 시 병합 → Langfuse 새 버전 등록 (staging label) → production label 이동 → webhook → AI 서버 프롬프트 버전 갱신
- **staging 확인:** 새 버전으로 실제 운영 제출물을 채점 → judge 자동 판정, 사람 확인 → production 승격
- **실패 리포트:** PR 코멘트로 실패 원인, 문제 샘플, 개선 제안 → 개발자 검토 → 수정
- **프롬프트 I/O 계약 변경:** 새 계약의 프롬프트 먼저 작성 → AI 서버 수정·배포 → 운영 프롬프트 버전 업그레이드
- **운영 확인:** 운영 표본 평가(채점 품질 검증 루프 사례), 대시보드, 임계값 알림
- **대응 경로**

| 상황 | 경로 |
|---|---|
| 일반 변경, 치명적이지 않은 문제 | 평가 게이트를 거쳐 새 버전으로 roll-forward |
| 치명적 문제 | Langfuse label을 직전 버전으로 롤백 (webhook으로 반영) |
| 롤백할 수 없는 핫픽스 | Langfuse 수동 등록 (게이트 우회 예외) |

## 결과

| 지표 | 값 | 측정 기준 |
|---|---|---|
| 프롬프트 교체 | 재배포 없음 | 프롬프트 I/O 계약이 바뀌지 않는 변경 |
| 프롬프트 롤백 | label 변경만 | 프롬프트 I/O 계약이 같은 버전 사이 |
| 병합 조건 | 평가 게이트 통과 | 프롬프트 변경 PR. 핫픽스 수동 등록만 예외 |

## 한계와 다음 단계

- **병합 임계치는 아직 조정 중이다.** 수용 기준을 숫자로 확정하지 못해 팀 논의로 조정하고 있다(채점 품질 검증 루프 사례).
- **프롬프트 I/O 계약이 바뀐 버전은 label만으로 되돌릴 수 없다.** AI 서버는 새 계약의 키와 타입을 검사한다. 이때는 서버 배포가 함께 필요하다.
- **staging 확인 뒤에는 전체에 한 번에 적용된다.** staging은 운영 제출물 일부로만 확인한다. 놓친 문제는 운영 표본 평가가 잡을 때까지 모든 학생에게 영향을 준다.
- **다음 단계는 섀도 테스트나 카나리 배포다.** 섀도 테스트는 새 버전 결과를 학생에게 보이지 않고 judge로 비교한다. 둘 다 label·webhook 구조 위에 붙일 수 있다.
